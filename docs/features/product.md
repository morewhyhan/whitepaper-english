# 白纸英语产品规格

## 背景与目标

白纸英语（WhitePaper English）的产品真源来自用户提供的 [BUSINESS_MODEL.md](../../BUSINESS_MODEL.md) V1.0，以及本聊天中对 A4 白纸学习方式的讨论。本文件把已经采用的产品方向写成可执行的目标规格；它不把尚未写入源码的能力伪装成当前功能。

当前仓库仍保留 Ignite 的工程底座和模板业务，代码采用另有 Plan 和验收记录。本文件先把“采用后应该是什么”说清楚，当前实现事实见 [Design 入口](../designs/README.md)。

## 一句话定位

白纸英语是一张由学习者自己主导的英语学习白纸：用户可以直接写、直接判断、直接复盘，并带走自己的词表、原文和学习成果。

品牌语：**直接写，直接学。**

## 采用决策

以下决策作为第一阶段的产品基线，不再把它们留作开工前悬案：

1. **先做词汇白纸。** 第一阶段只把 A4 白纸式词汇循环做成真实功能；写作和语法可以显示工作台入口与页面外壳，但不开放实际学习功能或伪造学习结果。
2. **游客先用，登录可选。** 未登录用户可以打开白纸、输入或导入词表、完成本地学习并导出；登录只增加账户侧保存、同步和跨设备恢复，不成为第一次使用的门槛。
3. **Tasks 只作为模板历史。** Tasks 不是白纸英语的业务模型。采用时以词表、学习任务、轮次和判断记录替换它；模板示例数据不作为白纸英语用户数据迁移目标。
4. **工程底座保留。** Next.js、React、TypeScript、Hono Typed RPC、Prisma、React Query、Better Auth、基础 UI 组件和测试治理继续使用；替换的是产品身份、页面外壳、领域模型和学习行为。
5. **视觉采用纸张基线。** 背景为纸张米白，正文为黑字，边界用细线和留白表达；浅绿/浅红只表达判断状态，并始终同时显示“会/不会”等文字。
6. **白纸是工作台外壳。** 背单词、写作和学语法是三种独立的纸张模式；当前纸张一次只承载一种学习任务，不把三种内容纵向堆在同一张纸上。
7. **词汇采用词书纸摞。** 用户可以在多本词书之间切换；每本词书作为一摞纸管理，当前学习纸是这摞纸的活动纸张，切换词书不覆盖其他词书的进度。
8. **语法先按三个等级组织。** 语法入口分为低级语法、中级语法和高级语法；用户提供的语法机制仓库作为后续内容接入和审计来源，不在本轮把它伪装成已接入能力。
9. **写作保持自由输入。** 写作不要求用户先选固定题目、课程或模板；用户可以直接建立自己的写作纸，后续反馈必须围绕用户原文工作。

## 用户与价值

首发对象是中文母语的成年自主英语学习者；大学生和青年学习者是传播切口，不构成强制年龄限制。用户不需要先选择课程或完成统一等级，能够从一组具体的词、一个想写的句子或一个语法疑问开始。

产品价值不是替用户打出一个“掌握分数”，而是让用户留下可以继续修改和带走的学习成果：词汇自评记录、写作原文与版本、语法作答与确认后的总结。

## 产品阶段

```text
第一阶段：词汇白纸 —— 输入/导入 → 一页扫词 → 会/不会 → 不会词进入下一轮 → 导出/保存
第二阶段：直接写作 —— 用户原文 → 可控反馈 → 接受/忽略/撤销 → 保留原文
第三阶段：语法机制 —— 自己作答 → 追问与提示 → 新情境复验 → 用户确认总结
第四阶段：共享学习档案 —— 三类成果互相引用，但不合并成一个掌握分数
```

- [词汇白纸](./vocabulary.md)：负责词表、扫词、判断、轮次和困难词上下文。
- [写作](./writing.md)：负责用户原文及其可控反馈；不要求先完成词汇或语法。

## 业务规则

- R1（REQ-ADOPTION-001）：产品身份统一使用“白纸英语 / WhitePaper English”，仓库为 `morewhyhan/whitepaper-english`；品牌、站点说明、导航、cookie slug、README 和 `.ai` 项目身份必须使用同一份命名。
- R2（REQ-ADOPTION-002）：工程底座沿用模板的类型安全、认证边界、模块目录、RPC、Prisma 和验证体系；产品名称、首页、工作台、导航、视觉和业务领域不继续使用 Ignite 示例语义。
- R3（REQ-WHITEPAPER-001）：用户拥有自己的输入、判断、原文和确认后的成果；基础内容可编辑、可导出，AI 辅助不能替用户宣布掌握。
- R4（REQ-WHITEPAPER-002）：页面遵循纸张、黑字、留白、低干扰和窄屏可读性；任何颜色状态都有文字、名称或其他可访问表达。
- R5（REQ-WHITEPAPER-003）：本阶段不自动开通付费、云服务、教材分发或外部模型；需要这些能力时另立规格、权限、成本和验收。
- R6（REQ-WHITEPAPER-004）：未登录用户可以开始第一阶段词汇学习；账户只用于同步、备份和跨设备恢复。
- R7（REQ-WHITEPAPER-005）：第一阶段的首屏直接进入词汇白纸，不先展示 Tasks、设置或模板说明；写作和语法在未实现前不得展示为可用学习功能。
- R8（REQ-ACCOUNT-001）：学习状态接口只接受 session 身份。未登录访问返回 401；客户端传入的用户标识不能改变身份。账号数据的持久化和双账号隔离在独立 Plan 中定义规格与验收。
- R9（REQ-ACCOUNT-002）：学习数据按账号持久化并隔离。两个账号保存的词状态互不可见，读取只返回当前 session 用户自己的记录。
- R10（REQ-ACCOUNT-003）：学习状态接口返回当前 session 用户已经保存的词状态，而不是固定空数组。
- R11（REQ-ACCOUNT-004）：词汇白纸提供可见的登录入口；登录或注册成功后回到词汇白纸，退出后回到访客状态。
- R12（REQ-ACCOUNT-005）：登录用户可以批量提交当前页的会/不会判定；同一账号同一词重复提交时覆盖旧值，其他账号不可见。
- R13（REQ-ACCOUNT-006）：登录用户点“下一页”时，当前页的判定提交到自己的账号；未登录用户只保存在本机。
- R14（REQ-ACCOUNT-007）：登录用户点“撤销上一页”时，清空该页在账号里的判定并只回退一页；刷新后该页不再显示为已判定。
- R15（REQ-ACCOUNT-008）：登录用户的每日轮次、页码和判定按账号保存；清掉本机存储或换标签页后刷新，仍能回到同一轮同一页。

## 验收标准

- AC-ADOPTION-001（REQ-ADOPTION-001）：Given 项目完成身份采用，When 检查 README、站点配置、项目身份、cookie slug、导航和仓库信息，Then 全部使用白纸英语命名，原始 BUSINESS_MODEL.md 未被改写。
- AC-ADOPTION-002（REQ-ADOPTION-002）：Given 保留模板工程底座，When 检查目录和依赖，Then Next.js、React、TypeScript、Hono、Prisma、React Query、Better Auth 与测试治理仍可用，且产品界面不再以 Ignite 作为用户-facing 身份。
- AC-WHITEPAPER-001（REQ-WHITEPAPER-001）：Given 用户形成词表、原文或总结，When 编辑、保存或导出，Then 用户原始内容和确认后的版本可找回，辅助内容不会覆盖原文。
- AC-WHITEPAPER-002（REQ-WHITEPAPER-002）：Given 桌面或窄屏学习路径，When 用户完成一次判断，Then 文字可读、控件可达、会/不会状态不只依赖颜色。
- AC-WHITEPAPER-003（REQ-WHITEPAPER-003）：Given 当前阶段未接入付费、云服务或外部模型，When 核对页面和运行配置，Then 不出现虚假的商业能力或已完成的 AI 结果。
- AC-WHITEPAPER-004（REQ-WHITEPAPER-004）：Given 未登录访客，When 打开首页并点击第一入口，Then 不需要注册即可进入词汇白纸并开始本地学习。
- AC-WHITEPAPER-005（REQ-WHITEPAPER-005）：Given 第一阶段产品入口，When 访问首页和工作台，Then 第一动作是进入词汇白纸，未实现的写作/语法不被误标为可用。
- AC-ACCOUNT-001（REQ-ACCOUNT-001）：Given 游客或登录用户，When 请求 /api/vocabulary/state，Then 游客返回 401，游客携带 userId 参数仍返回 401，登录用户返回 200 和 { data: { activeBook: null, wordStates: [] } }。客户端 userId 不能改变游客身份。
- AC-ACCOUNT-002（REQ-ACCOUNT-002）：Given 账号 A 和账号 B 各自保存词状态，When 分别读取自己的词状态，Then 只返回本账号保存的记录，看不到对方的记录。
- AC-ACCOUNT-003（REQ-ACCOUNT-003）：Given 账号 A 已保存词状态，When A 请求 /api/vocabulary/state，Then 返回 A 自己的词状态，而不是空数组。
- AC-ACCOUNT-004（REQ-ACCOUNT-004）：Given 访客打开词汇白纸，When 点击登录并完成注册，Then 回到 /vocabulary 且显示退出；点击退出后重新显示登录。
- AC-ACCOUNT-005（REQ-ACCOUNT-005）：Given 登录用户 A 提交 apple=true、tree=false，When 再提交 apple=false，Then 读取只保留 apple=false 和一条 tree=false；账号 B 读取不到 A 的记录。
- AC-ACCOUNT-006（REQ-ACCOUNT-006）：Given 登录用户在词汇白纸第一页，When 点击“下一页”，Then 当前页判定写入账号，读取状态返回这些词。
- AC-ACCOUNT-007（REQ-ACCOUNT-007）：Given 登录用户已提交第一页并进入第二页，When 点击“撤销上一页”，Then 第一页的词从账号状态中删除，页面回到第一页且判定为空。
- AC-ACCOUNT-008（REQ-ACCOUNT-008）：Given 登录用户已进入第二页，When 清除本地存储并刷新，Then 仍回到第二页，“撤销上一页”可用。

## 后续讨论边界

第一阶段验收以 Web 端桌面浏览器为当前门槛；移动端浏览器验收按 2026-11-08 用户决定暂缓，恢复时重新纳入对应规格和 Plan。

第一阶段之外仍需讨论关联材料的来源和质量、长期复习节奏、写作反馈的供应商与隐私、语法内容资产的授权与课程组织。这些问题不会阻止第一阶段文档基线，但在进入对应阶段前必须另行关闭。
