# 语法机制测试用例

对应 docs/GOAL.md 的 REQ-GRAMMAR-001..009。当前均为待实现用例。

## AC-GRAMMAR-001 课程目录

- 场景：打开学语法。
- 通过：141 张 reviewed 卡按 G_INDEX order 排列；缺口保留；未 review 卡不可进入；等级不显示掌握。
- 不过：按文件名排序、补写缺口、出现未审卡、等级被标成掌握。
- 未覆盖：课程正文质量、题目质量。

## AC-GRAMMAR-002 单机制单题

- 场景：进入 G001，存在未通过机制。
- 通过：定位第一个未通过机制，一次只显示一道题；回答前无答案；不能批量提交或跳机制。
- 不过：整课讲授、一次多题、提前显示答案、跳过机制。
- 未覆盖：题目难度是否合适。

## AC-GRAMMAR-003 判题与证据

- 场景：提交回答。
- 通过：先判题目有效性，再分类目标/非目标/猜测/提示；只有无提示新情境证据充分才通过。
- 不过：自动通过、把非目标拼写错误判成机制失败、重复原题当迁移证据。
- 未覆盖：模型本身的语言能力上限。

## AC-GRAMMAR-004 状态持久化

- 场景：机制通过或失败后推进。
- 通过：先保存进度、最近十题来源和错题，再显示下一题；失败显示未保存。
- 不过：先推进后保存、保存失败仍显示已通过、刷新丢失。
- 未覆盖：跨设备冲突合并。

## AC-GRAMMAR-005 错题与复验

- 场景：目标机制答错。
- 通过：追加错题、保留旧记录、最小讲解、换未见过的新题复验。
- 不过：覆盖旧错题、重复原题、提示后答案算通过。
- 未覆盖：错题长期复习算法。

## AC-GRAMMAR-006 整课总结

- 场景：当前 G 全部可评估机制通过。
- 通过：闭卷用户总结，按完整/准确/精炼/清楚/独立校验，通过才记录 G 和原文。
- 不过：跳过总结、AI 改写替代原文、未全通过就记 G。
- 未覆盖：总结质量的人工复核。

## AC-GRAMMAR-007 内容版本与边界

- 场景：发布内置语法内容。
- 通过：快照提交号、G_INDEX、141 张 reviewed 卡、来源可追溯；共享卡只记 progress_key；无未审卡和虚构正文。
- 不过：运行时从 GitHub 拉取、补写缺失正文、把共享卡拆成单个 G、许可未确认就发布。
- 未覆盖：来源 PDF 的版权许可。

## AC-GRAMMAR-008 模块隔离

- 场景：有词汇判定后进入学语法。
- 通过：语法进度只来自语法证据；词汇不被改写；tab 位置稳定；写作未开放。
- 不过：把词汇完成折算成语法掌握、切换 tab 跳动、写作被标成可用。
- 未覆盖：同一账号多设备同步。

## AC-GRAMMAR-009 AI 不可用

- 场景：AI 未配置或调用失败。
- 通过：只读机制卡和目录；不生成题目、不判分、不写掌握；客户端无模型凭据。
- 不过：伪造 AI 判题、自动写通过、把 API key 发到客户端。
- 未覆盖：模型供应商可用性和成本。
