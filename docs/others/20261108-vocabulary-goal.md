# 白纸英语 V1 完成目标（GOAL 提示词）

> 用法：把本文件从「一、角色」开始的内容作为任务提示交给执行代理。它是目标，不是 Plan。执行时按仓库规则创建并推进 Plan。
>
> 设计依据：
>
> - SMART 目标：具体、可衡量、可达成、相关、有时限。
> - Locke 与 Latham 的目标设定理论：具体且有难度的目标配合反馈，比“尽力而为”更有效。
> - Anthropic 提示词原则：清晰直接、提供上下文、结构化、给例子。
> - 仓库自身的 [Plan 规则](../plans/README.md) 和 [测试标准](../standards/testing.md)。

# 一、角色与最终结果

你是白纸英语的技术负责人和产品工程师。把这个仓库从“能跑的词汇原型”推进到“可交付的 V1”：一个 Web 端的词汇白纸，用户注册后每天扫完一本词书，看到中文释义和发音，用 1:8 关联网络理解生词，扫完清零，第二天重新开始；设置里有账户、学习记录、声音、判定和重置。

完成的定义不是“代码写完”，是：真实用户能走通完整路径，所有检查通过，规格、设计、测试和运行证据一致。

# 四、硬约束

不满足以下任何一条，交付不算完成：

1. 只做 Web 端桌面浏览器。移动端验收暂缓，不修移动端。
2. 不提供导入、导出和清空全部。只提供“重置今天这本书”。
3. 同一时间只有一本活动词书。切换词书保留另一本进度；开始新书就是新书的完整首轮。
4. 九宫格固定每页 4 组共 36 词。没有 6 组，也没有 54 词一页。
5. 关联辅助一页只放一组 1:8，不判定，不做 4 组或 6 组。
6. 回到上一页会清空该页已提交的判定，只回退一页。
7. 账号可选：登录后数据归账号；未登录数据只在本机；登录时询问是否并入账号，不静默合并。
8. 释义优先级：《新概念英语》原文、平行世界三份阅读、ECDICT 常用义。
9. 新概念正文和付费阅读不能复制进产品，也不能随数据包分发。只用于判断词义，关联句自己生成。
10. 发音每次点击都播，声音短、清晰、顺滑；系统语音优先，效果不足再预生成音频。
11. 不伪造红灯、审查或运行证据。不跳过失败检查。不 `git push`，除非用户明确要求。
12. 不重写已应用的 Prisma migration。账号数据用追加式迁移。

# 五、可验证的完成标准

全部满足才算 V1 完成：

## 工程门禁

依次运行并通过：

    pnpm runtime:check
    pnpm template:doctor
    pnpm ignite validate
    pnpm docs:check
    pnpm typecheck
    pnpm tools:check
    pnpm lint
    pnpm format:check
    pnpm test
    pnpm test:migrations
    pnpm build
    pnpm test:e2e:web

`pnpm test:e2e:web` 只跑 desktop-chromium。任何一条失败都必须修复，不能用“已知问题”略过。

## 账号与数据

- 能注册、登录、退出；两个账号的数据互不可见。
- 账号数据存数据库：词书、词状态、每日会话、轮次、判断、日聚合。
- 未登录可学习；登录时提示是否把本机进度并入账号。
- 刷新、换标签页、重新登录后进度可恢复。

## 学习闭环

- 每页 4 组共 36 词，尾页按实际数量。
- 普通点击和 Shift 点击语义可互换；未点击词按当页默认提交。
- 标“不会”立即显示中文，格子不移动。
- 点“下一页”提交并推进；回到上一页清空该页判定，只回退一页。
- 一轮结束只保留不会词；清零且全量首轮覆盖后显示通关页，文案用“今天，清零了。”。
- 第二天建立完整首轮，昨天记录保留为未完成。
- 同一时间只有一本活动词书。

## 释义与发音

- 3,975 条词条每一条都有确定结果：一个义项，或明确标注“暂无释义”及原因。不能静默留空。
- 多义词按原文语境取义；抽 100 个词人工核对。
- 中文在英文上方，固定高度，未判定时隐藏，标不会后显示。
- 点击词条播放美式发音；系统无语音时判定照常。
- 设置可静音。

## 关联辅助

- 每个目标词都有完整 8 条可验证关联，或明确记录无法补齐的原因。
- 句子真实、自然、语法正确，同时包含目标词和外围词，4 到 9 个词。
- 外围词优先级：当前词书会词、当前词书其他词、其他词书会词、通用词。
- 一页一组 1:8，无箭头，句子在中间，不判定。
- 前台只读缓存，不调用模型；单页加载低于 300 毫秒。
- 抽 200 组人工审核，合格率不低于 90%。

## 设置与学习记录

- 设置是大面板，左侧分类、右侧内容，窄屏列表优先。
- 分类包含账户、学习记录、发音与声音、判定与操作、词书与数据、外观。
- 学习记录显示当前词书按天的首轮识别率曲线；点某天看词数、会、不会、轮次、是否完成、用时。
- “重置今天这本书”清空当天轮次和判定，重新全量首轮，历史记录保留。
- 账户分类显示当前账号；未登录显示访客状态。

# 六、工作方式

1. 一个可独立验收的交付建一个 Plan。用 `pnpm create:change <name>` 或 `pnpm create:module <name>`，不要手写编号。
2. Plan 按 prepare、red、implement、verify 推进。先写测试并取得真实红灯，再实现。
3. 每个 Plan 完成 draft 审查和 delivery 审查；用仓库命令记录，不伪造审查人。
4. 运行 `pnpm ignite check --plan <ID> --level integration`，通过后才标记 done。
5. 所有 Plan 完成后运行 `pnpm ignite release verify <release> --plan <done-plan-id>`。
6. 设计事实改完回写 `docs/designs/`，规格变化回写 `docs/features/`，不要只改代码。
7. 两个历史 draft Plan 不要强行完成。新 Plan 覆盖它们时，把它们标记为 superseded，保留记录。
8. 可以委派独立审查或并行切片，但共享文件只留一个写入者，审查不能用作者自评代替。

# 七、分阶段任务

## M1 账号与学习数据

结果：用户能注册登录，学习数据按账号保存，核心闭环在新数据模型上跑通。

范围：挂载登录入口；Prisma 模型和迁移；账号数据 API；单本活动词书；36 词分页；下一页提交、上一页清空；每日重置；通关页；重置今天这本书。

验收：两个账号数据隔离；刷新恢复；跨天新首轮；上一页清空；通关页出现；Web 端到端通过。

## M2 释义、发音与设置

结果：每个词都有确定释义，点词能听到发音，设置能改声音和判定。

范围：ECDICT 导入；新概念与三份阅读的义项提取；3,975 条回填；释义排版按原型；系统语音；设置两栏与分类；学习记录曲线。

验收：释义覆盖率 100% 有结论；抽 100 词核对；发音可用；设置分类可用；曲线显示正确。

## M3 关联辅助

结果：任意目标词打开一页 1:8，8 条句子真实可读，不判定。

范围：本地向量构建；top-24 候选；层级筛选；句子生成与双模型评审；LanguageTool 校验；数据分片；关联页。

验收：覆盖率 100% 或有记录；抽 200 组合格率 90%；单页加载低于 300 毫秒；前台无模型调用。

## M4 收口与发布

结果：整条路径可交付，文档与事实一致。

范围：账号合并、边界状态、无障碍、性能、设计回写、Release 验证。

验收：全部工程门禁通过；Release verify 通过；`docs/designs/` 与实现一致。

# 八、阻塞与停止条件

- 产品决定缺失且文档没有依据：写进 Plan 的 open_questions，继续做不依赖它的部分。只有完全无法推进时才阻塞。
- 版权冲突：新概念或付费阅读不能进产品时，改用 ECDICT 和生成的句子，并在 Plan 记录取舍。
- 检查失败：修复根因，不跳过、不降低标准。
- 数据缺口：不允许用编造的释义或句子填满覆盖率。
- 时间压力：砍范围并写清砍了什么，不减少验收项。

# 九、报告格式

每次交付报告包含：

1. 实际完成的结果，对应哪条 REQ/AC。
2. 运行过的命令和真实结果，包括失败。
3. 被测版本：提交号、环境。
4. 未完成项和影响。
5. 下一步。

不要用命令日志代替解释，不要把“测试通过”当成“用户目标完成”。
