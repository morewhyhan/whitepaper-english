# ADR-0005 关联辅助与词库数据管线

## 状态

已接受（2026-11-08）。

## 背景

1:8 关联网络要求真实性优先、按来源分层补满 8 个、前台不调用模型。围绕这条要求，向量模型、候选规模、句子生成、校验和词库数据都还没有长期决定。研究记录见 [关联辅助技术选型备忘](../association-research.md)。

约束来自 [词汇规格](../../features/vocabulary.md) 和 [PRD 摘录](../inputs/20261104-vocabulary-prd.md)：句子必须真实自然、同时包含两个词；来源优先当前词书；关联页只读；内置词书离线分发；自定义词书走同一管线；Web 端优先，当前没有服务端账户。

## 决策

1. **向量本地生成。** 使用 bge-small-en-v1.5（384 维）在构建期批量编码，不调用托管向量 API。前端不加载模型。
2. **按语境编码义项。** 输入是「词 + 该书原句」；没有原句时用 ECDICT 首选释义拼一个短上下文。没有上下文才退回词形向量。
3. **不做向量数据库。** 15k 词乘 384 维在构建期做精确余弦，每个目标词预先取 24 个候选。前端只读邻居列表。
4. **句子批量生成，双模型加规则校验。** 便宜模型批量写句子，另一个模型做语义评审，LanguageTool 查语法，再用 ECDICT 的 exchange 检查词形。首批人工抽检 200 组，之后每批 50 组。
5. **第一版提供完整 1:8。** 内置词书和自定义词书都必须生成完整 8 条。自定义词书导入后进入后台生成任务，生成期间关联入口显示「生成中」，不静默降级成 4 条或空网络。
6. **词义与词形数据用 ECDICT。** 采用 MIT 许可的中文释义、音标、词频、考试标签和 exchange 字段。显示时清洗词性标记，原始字段保留。
7. **预置词书按词频分层。** 使用 ECDICT 的 BNC 和当代语料库排名生成核心 1000、常用 3000、进阶 6000 三档。四级、六级、考研等标签只作为词条元数据展示，不作为预置词书的唯一来源，避免把非官方考纲当成权威词表。
8. **发音先用系统语音。** 使用 Web Speech API 选择 en-US 声音；真实使用中音色问题明显时，再为内置词书预生成音频，交互不变。
9. **数据按词书和首字母分片。** 每条约 10 到 12 MB 原始 JSON，gzip 后 3 到 4 MB；前端按当前页 36 个目标加载。自定义词书结果存 IndexedDB。

## 替代方案

- **托管向量 API**：否决。词表虽然不含用户隐私，但会引入网络依赖、密钥和持续成本；本地小模型在英文词表上足够。
- **向量数据库**：否决。4k 到 20k 词的精确余弦在构建期几秒完成，运行时不需要检索服务。
- **只用真实语料检索句子**：否决。Tatoeba 等语料对任意词对覆盖率低，句长和难度不可控，无法稳定补满 8 条。
- **运行时调用 LLM 生成**：否决。延迟、成本和离线可用性都不符合「打开就有」。
- **自定义词书暂不提供关联**：否决。用户要求第一版完整。
- **以考试标签作为预置词书主来源**：否决。标签是词典标注，不是官方考纲，覆盖和权威性都不足。

## 代价与风险

- 构建管线变重：需要本地模型、批量生成、双模型评审和人工抽检，首次生成是一次性工程。
- 生成成本存在，但由构建期承担，用户使用时没有模型调用。
- 句子质量依赖生成与评审，仍会有漏网错误；用户举报和抽样是必要补充。
- 自定义词书要等后台生成，导入后不能立刻用关联；界面必须说清楚状态。
- ECDICT 对 3,975 个词的覆盖需要先核对，缺失词条要单独处理。
- 本地模型只在构建期使用，贡献者需要能跑 Node 或 Python 构建脚本。

## 影响

- 词汇规格的关联辅助、发音、初始词书和多词书章节按本决策更新。
- 实现 Plan 需要新增构建脚本、数据分片和生成任务，不属于现有应用运行时。
- 设计文档在实现完成后回写实际的数据格式和加载路径。

## 复审条件

- 人工抽检合格率低于 90%，或用户举报集中在真实性和自然度。
- 自定义词书生成等待时间超过可接受范围。
- ECDICT 覆盖低于 90%，或释义质量不适合四级和专升本难度。
- 系统语音在真实设备上不可用或音色明显影响使用。
- 关联数据单页加载超过 300 毫秒。
